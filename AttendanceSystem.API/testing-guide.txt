# 🧪 Testing Guide V2 - Attendance System API

Base URL: `http://localhost:5152` (cek port aktual dari `dotnet run`)

> ⚠️ Struktur database sudah berubah dari testing sebelumnya:
> - `Employee` **tidak lagi punya `email`** (email sekarang cuma ada di `User`)
> - `Employee` sekarang punya `nik` (opsional, unique)
> - `Employee.departmentId` sekarang **opsional** (boleh null)
> - Relasi User↔Employee dibalik: `Employee.userId` (bukan `User.employeeId`)
> - Field attendance: `attendanceDate` (bukan `date`), `checkIn`/`checkOut` sekarang **tanggal+jam lengkap** (bukan cuma jam), `notes` (bukan `note`)

## 1️⃣ SHIFT — Testing sebagai Admin/HR

Header semua request: `Authorization: Bearer {TOKEN_ADMIN}` atau `{TOKEN_HR}`

### 1.1 Create Shift — Shift Pagi
```
POST /api/shift
```
```json
{
  "name": "Shift Pagi",
  "startTime": "08:00:00",
  "endTime": "17:00:00",
  "gracePeriodMinutes": 15
}
```
**Expected:** `201 Created`, dapat `id` → 📋 **simpan sebagai `SHIFT_ID_PAGI`**

### 1.2 Create Shift — Shift Malam (buat variasi testing)
```
POST /api/shift
```
```json
{
  "name": "Shift Malam",
  "startTime": "20:00:00",
  "endTime": "05:00:00",
  "gracePeriodMinutes": 10
}
```
📋 **simpan sebagai `SHIFT_ID_MALAM`**

### 1.3 Create Shift dengan Jam Salah (Harus Gagal)
```
POST /api/shift
```
```json
{
  "name": "Shift Error",
  "startTime": "17:00:00",
  "endTime": "08:00:00",
  "gracePeriodMinutes": 0
}
```
**Expected:** `400 Bad Request` → `"Jam selesai harus lebih besar dari jam mulai"`

> Catatan: untuk shift malam yang beneran lewat tengah malam (jam 20:00–05:00), validasi sederhana ini sebenarnya akan nolak juga karena `endTime < startTime`. Kalau kamu butuh shift lintas hari beneran, kasih tau nanti kita perbaiki validasinya (butuh logic tambahan).

### 1.4 Get All Shifts
```
GET /api/shift
```
**Expected:** Muncul "Shift Pagi" (dan "Shift Malam" kalau 1.2 berhasil)

### 1.5 Get by ID
```
GET /api/shift/{SHIFT_ID_PAGI}
```

### 1.6 Update Shift
```
PUT /api/shift/{SHIFT_ID_PAGI}
```
```json
{
  "name": "Shift Pagi Updated",
  "startTime": "08:30:00",
  "endTime": "17:30:00",
  "gracePeriodMinutes": 20
}
```
**Expected:** `200 OK` → `"Shift berhasil diupdate"`

### 1.7 Employee Coba Create Shift (Harus Ditolak)

```

```
**Expected:** `403 Forbidden`

### 1.9 Admin Delete Shift (Harus Berhasil)
```

```
**Expected:** `200 OK` → `"Shift berhasil dihapus"`

> ⚠️ Setelah step ini, `SHIFT_ID_PAGI` sudah terhapus. Kalau butuh shift buat testing selanjutnya, pakai `SHIFT_ID_MALAM` atau buat shift baru.

## 🔜 Yang Belum Ada (Untuk Dikerjakan Nanti)

- **Attendance belum pakai `shiftId`** — saat ini `AttendanceController.CheckIn` masih hardcode jam standar `08:00` + toleransi 15 menit, belum menarik data dari tabel `Shifts` yang beneran di-assign ke karyawan. Perlu ditambahkan: field `shiftId` di `Employee` (karyawan pakai shift apa) atau di request check-in.
- **Leave belum otomatis mempengaruhi status Attendance** — idealnya kalau leave di-approve untuk tanggal tertentu, sistem otomatis bikin record `Attendance` dengan `status: "Leave"` di tanggal itu, biar muncul di laporan absensi. Ini belum diimplementasi.
- **Reports API** (Monthly Report, Employee Report, Department Report) belum dibuat.

Kabari kalau mau lanjut ke salah satu poin di atas, atau pindah ke **WPF Frontend**.
